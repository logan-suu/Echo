## 🔄 文档同步更新

请按 Echo 项目 AGENTS.md 的文档问题处理流程（§12.4）和决策同步规范执行：

### 第一步：确定同步范围
1. **如果用户提供了决策内容**（如“选择方案 A，Actor 不标注 @MainActor”）：
   - 记录决策摘要。
   - 定位该决策涉及的所有文档。
2. **如果用户未提供具体内容**：
   - 读取 `docs/05-planning/task-status.json` 中最近的 `documentation_conflicts` 记录，以及 `docs/05-planning/deferred-items.json`。
   - 找到最新的一条待处理的冲突/决策记录。
   - 输出：“检测到待同步的决策：[决策摘要]。”
3. **自动扫描关联文档**：
   - 根据决策涉及的用户故事编号（如 US-PRV-001），查找引用该故事的所有文档。
   - 如果决策涉及架构概念（如 Actor 隔离），检索所有包含该概念的文档。

### 第二步：执行同步
1. **更新规格书**（如涉及 AC）：
   - 定位到 `docs/01-spec/用户故事与验收标准规格书.md` 中对应的故事。
   - 按决策修改 AC 原文或注释。
   - 标记修改日期和决策人。
2. **更新架构设计文档**（如涉及架构）：
   - 定位到 `docs/02-architecture/架构设计文档.md` 中对应的章节。
   - 按决策修改契约描述或示例代码。
3. **更新避坑手册**（如涉及陷阱）：
   - 定位到 `docs/03-implementation/开发避坑与关键注意点手册.md`。
   - 如有新增陷阱，添加到对应章节；如有废弃规则，标记为过时。
4. **更新其他文档**：
   - 双语言实现说明文档（如涉及跨语言策略）。
   - 数据流文档（如涉及 Pipeline 流程变更）。
   - AI Native 开发理念手册（如涉及开发流程变更）。
5. **更新 AGENTS.md**（如有必要）：
   - 如果规约发生变化（如新增红线或契约），更新对应章节。
   - 更新版本号和变更日志。

### 第三步：记录决策
1. 更新 `docs/05-planning/task-status.json`：
    - 在 `documentation_conflicts` 数组中记录该决策。
    - 状态标记为 `resolved`。
    - 记录决策时间、决策人和方案编号。
2. 如果决策涉及延期任务，同步更新 `docs/05-planning/deferred-items.json`（如移至 `resolved_deferred` 或更新 `last_checked_at`）。

### 第四步：输出变更摘要
1. 列出所有修改的文件：
   | 文件路径 | 修改内容摘要 |
   | --- | --- |
   | `docs/01-spec/用户故事与验收标准规格书.md` | 修改 US-PRV-001 AC-3 |
   | `docs/02-architecture/架构设计文档.md` | 更新 §4.2 Actor 隔离契约 |
   | `AGENTS.md` | 更新版本号至 v5.6 |
2. **如果有 PR 关联**：将变更摘要评论到当前 PR 中。
3. 提示用户：“✅ 文档同步完成，请审查变更并提交 PR。”
