## 🔗 阶段集成测试

请按 Echo 项目 AGENTS.md 的阶段集成测试契约（§12.6）执行：

### 第一步：确定阶段
1. 读取 `docs/05-planning/task-status.json`。
2. 获取 `current_phase`（如 "1"）。
3. 如果用户指定了阶段 ID（如 `test-phase-echo 2`），以用户指定的为准。
4. **前置条件检查**：
   - 读取 task-status.json，检查当前阶段所有任务的 `status`。
   - 如果存在 `in_progress` 的任务，提示：“当前阶段有任务尚未完成，请先完成后再执行集成测试。”
   - 如果存在 `blocked` 的任务，提示：“当前阶段有任务被阻断，请先解决后再执行集成测试。”
   - 如果所有任务均已完成，才继续执行。

### 第二步：执行测试
1. 确定测试范围：
   - 如果用户指定了阶段 ID，使用 `--filter "Phase[阶段ID]"`
   - 如果未指定，使用 `--filter "Phase[current_phase]"`
2. 运行对应的集成测试命令：
       ```bash
       swift test --filter "Phase[阶段ID]"
       ```
   （使用引号确保通配符不被 shell 解释）
3. 注意：集成测试可能耗时较长，请耐心等待。
4. **如果没有找到对应的测试套件**：
   - 输出：“该阶段未配置独立的集成测试套件。”
   - 建议：“是否要运行全量集成测试？请执行 `test-integration-echo`。”

### 第三步：报告与门禁
1. **生成测试报告**（格式如下）：
       ```markdown
       ## 🔗 阶段集成测试报告
       - **阶段**：Phase X - [阶段名称]
       - **结果**：✅ 通过 / ❌ 失败
       - **用例数**：X 个通过 / Y 个失败 / Z 个跳过
       - **耗时**：[时间]
       - **失败详情**：[如有，列出失败的测试名称和错误摘要]
       - **涉及模块**：[涉及的 Pipeline 或 Actor]
       ```
2. **通过时**：
   - 更新 `task-status.json` 中该阶段的 `integration_test` 为 `passed`。
   - 输出：“✅ 阶段 X 集成测试通过，准备进入下一阶段。”
   - 询问用户是否执行 `next-task-echo` 开始下一阶段的任务。
3. **失败时**：
   - 更新 `integration_test` 为 `failed`。
   - 输出诊断建议（如“检查 SyncPipeline 的事务回滚逻辑”）。
   - **提供后续路径选项**：
     - 选项 A：修复代码后重新运行 `test-phase-echo`
     - 选项 B：标记为 blocked，暂停当前阶段（需说明原因）
     - 选项 C：跳过该阶段（需人类确认，仅限非关键阶段）

### 第四步：后续动作
如果测试通过，询问用户是否进入下一阶段或继续当前阶段的其他任务。
