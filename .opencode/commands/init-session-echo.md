## 🚀 新会话启动：Echo 项目初始化

你好，我是 Echo 项目的开发者。这是一个全新的会话，之前的对话历史不在上下文中。

请严格按照以下步骤执行初始化（这是我的项目规约 AGENTS.md 要求的流程），在确认状态前**不要**开始编写任何代码：

### 第一步：读取核心规约与地图
1. 读取项目根目录下的 `AGENTS.md`（项目宪法，定义所有红线与架构）。
2. 读取 `docs/INDEX.md`（文档地图，了解所有文档的位置）。
   - 如果 `docs/INDEX.md` 不存在，尝试读取 `docs/README.md`。
   - 如果都不存在，使用 `ls docs/` 列出目录结构，自行建立文档地图。

### 第二步：定位当前进度（任务溯源）
3. 读取 `docs/05-planning/task-status.json`。
   - **如果用户指定了任务 ID**（在会话中说了“我想做 2.3”），优先使用该任务：
     - **跨阶段阻断检查**：如果该任务属于阶段 N（N > 1），检查阶段 N-1 的集成测试任务（最后一个任务）是否为 `done`。
     - 如果不是 `done`，阻断并提示先完成前一阶段集成测试。
   - **如果用户未指定**：
     - 找出 `current_phase`（当前阶段）。
     - **跨阶段阻断检查**：如果 `current_phase > 1`，检查阶段 `current_phase - 1` 的集成测试任务是否为 `done`。
     - 如果不是 `done`，将 `current_phase` 修正为该阶段编号，并找到该集成测试任务作为当前任务。
     - 找到该阶段中第一个 `status: "ready"` 的任务。
     - 如果找不到 ready 任务，检查是否有 `in_progress` 的任务（可能是中断的）。
     - 如果都没有，列出当前阶段的所有 `backlog` 任务，让用户选择。
   - 确认该任务的所有 `dependencies`（依赖项）是否已标记为 `done`。
   - 如果找不到 ready 任务：
     - 输出：“✅ 当前没有待执行的任务。”
     - 列出当前阶段的所有任务状态摘要（已完成/进行中/待执行/被阻断）。
     - 询问用户：“是否要执行指定任务？（请提供任务 ID）”或“是否查看其他阶段的任务？”
   - 输出当前阶段、任务 ID、标题及关联的用户故事编号。

### 第三步：锁定规格上下文（防幻觉）
4. 根据上述任务 ID，查阅 `AGENTS.md` 中的“任务类型 → 文档快速索引”（§0.2）。
5. 读取本次任务需要参考的具体规格文档章节（例如 `docs/01-spec/...` 或 `docs/02-architecture/...`）。
6. 按以下格式输出上下文摘要：

```markdown
## 📋 任务上下文锁定

### 任务信息
- **任务 ID**：[任务ID]
- **标题**：[任务标题]
- **关联用户故事**：[US-XXX]
- **阶段**：Phase X - [阶段名称]

### 验收标准（AC）原文
> [逐字粘贴 AC-1 原文]
> [逐字粘贴 AC-2 原文]

### 关键架构约束
> [引用 AGENTS.md 中的相关规则]

### 依赖状态
- [依赖任务1]：✅ done
- [依赖任务2]：✅ done

### 参考文档
- `docs/01-spec/...`
- `docs/02-architecture/...`
```

7. **快速一致性检查**：
   - 检查该 AC 是否在 `AGENTS.md` 的“绝对红线”或“数据主权契约”中有对应规则。
   - 如果存在冲突，立即标记并等待用户确认。

### 第四步：状态确认与开工
8. 总结你当前的认知。
9. 等待我确认“开始执行”后：
   - 将 `task-status.json` 中该任务的 `status` 更新为 `in_progress`。
   - 再进入 TDD（测试驱动开发）编码流程。

请开始执行初始化。
```
