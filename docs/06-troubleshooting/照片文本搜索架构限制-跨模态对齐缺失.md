# 照片文本搜索架构限制（跨模态对齐缺失）

**状态**: v1 架构性限制（不可达）
**记录时间**: 2026-08-15（Phase 3F Live Review）
**关联规格**: US-RET-003、US-ING-004（均标记 Impossible/spec-invalid）
**关联文档**: `docs/02-architecture/技术选型文档.md` §1（SigLIP2 视觉）、§3（E5 文本）、`docs/05-planning/phase3f-story-matrix.md`
**关联延期**: 见 deferred-items.json（建议追踪条目）

---

## 一句话结论

在 v1 架构下，照片可以被**摄入**进 SigLIP2 视觉空间（768d），但**无法被文本语义搜索命中**。文本查询走 E5 文本空间（384d），两个空间之间没有学习到的跨模态对齐——这是规格层面明确的"不可能"项（Impossible/spec-invalid），不是接线 bug，也不属于 3F 修复范围。

## 症状（Live Review 实证）

- 34 张测试照片成功摄入：`dataSourceChangeSynced replaced=34, skipped=0, failed=0`，全部为 `visionDense` 表示（SigLIP2 真实推理）
- Search 输入 `flower` / `red` / `sunset`（针对照片）→ 始终"未找到记忆"
- 同一条搜索路径对**文本记忆**（Share 摄入，E5 空间）可正常命中（`西湖` → 返回「昨晚和朋友在西湖边看日落…」）
- 结论：**摄入正常、搜索链路正常，问题纯粹在"文本查询 → 视觉存储"这一段**（无跨模态通道）

## 架构根因

### 1. 两个独立的向量空间（技术选型强制分离）

| 空间 | 模型 | 维度 | 输入 |
| --- | --- | --- | --- |
| 文本 | multilingual-e5-small | 384d | 文本（query/passage 前缀注入） |
| 视觉 | SigLIP2-B/32-256 | 768d | 图像（256×256 预处理） |

两者无共享嵌入空间、无对齐矩阵、无联合训练（`docs/02-architecture/技术选型文档.md` §1/§3）。分代索引按空间隔离：`text_dense/e5-v1`（384d）与 `vision_dense/siglip2-v1`（768d）是**独立 HNSW**，向量不可互换比较。

### 2. 规格层面的矛盾（故事矩阵标记 Impossible）

> **US-RET-003**（故事矩阵）: "Text is specified as E5 while the AC requires query vectors in CLIP space." → Impossible/spec-invalid

> **US-ING-004**（故事矩阵）: "required direct text/vision-space alignment conflicts with the mandated E5/CLIP split."

即：AC 想要"文本搜照片"（CLIP 风格跨模态），但技术选型强制 E5（文本）与 SigLIP2（视觉）分离——两者在规格层面就不可调和，被 `3F.0` 标记为 Impossible/spec-invalid 保留。

### 3. 视觉通道仅支持"图搜图"

`SigLIP2Embedder.embedText(_:)` 直接抛错（`"SigLIP2Embedder does not support text embedding — use E5Embedder (R-3.1)"`）。vision_dense 通道的查询向量**必须由图像生成**，文本查询无法进入视觉空间。

## 为什么不是简单的接线修复

即使把生产搜索切换到 3F.6 的多通道 RRF（`searchMultiChannel` + `GenerationRoutedChannelAdapter`），文本查询在 vision_dense 通道仍**无法生成查询向量**：

- **text_dense 通道**：E5 文本查询 → 只在文本空间检索 → 不命中视觉存储（天然如此）
- **vision_dense 通道**：文本查询无法嵌入（SigLIP2 拒绝文本）→ 通道降级/空
- **lexical / ocr_text 通道**：仅对照片中**含文字**的内容有效（OCR/FTS）——对无文字照片无效；当前 `ocr_text`/`lexical` generation 也未物化

Live Review 的测试照片为纯色 + 几何图形（无文字），即使全通道融合也搜不到。

## 可行的未来路径（均超出 v1）

| 方案 | 思路 | 代价 / 阻碍 |
| --- | --- | --- |
| **CLIP 风格对齐模型** | 引入联合文本-图像嵌入（如 MobileCLIP），替代/补充 E5+SigLIP2 | 与强制 E5/CLIP 分离决策冲突；需重新技术选型（ADR 级变更） |
| **照片自动配文（VLM captioning）** | 端侧视觉-语言模型生成照片描述 → 描述文本入 E5 空间可被文本检索 | 需端侧 LLM/VLM 运行时（ADR-009 未获批，fail-closed） |
| **OCR 文本通道** | 照片内含文字经 OCR 入 ocr_text/lexical 通道 | 仅覆盖含文字照片；通道需物化 + 生产接线 |
| **文本-图像投影网络** | 在 E5 与 SigLIP2 之间学习投影矩阵 | 需成对训练数据；端侧推理成本；跨模型泛化风险 |

## 对用户的现实影响（v1）

- 用自然语言搜**照片**：不可用（v1 能力边界）
- 照片可浏览（详情页）、可编辑/删除、可被排除——但不参与文本检索
- 文本/语音记忆（Share 摄入）：检索完全正常（E5 空间内语义检索已验证）
