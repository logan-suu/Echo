# Echo · 回响：端侧 AI 技术选型决策记录

**版本**：v5.1b（§1~3 最终可用方案：MobileCLIP-B LT / multilingual-e5-small / SenseVoice Small；MobileCLIP2-S4 + Qwen3-0.6B 标记为 Phase 2 优化目标）

**更新日期**：2026-07-04

**适用范围**：iOS 18+ 端侧多模态检索、语音转写、文本嵌入、向量存储、推理框架及应用架构

**决策原则**：隐私优先 > 性能/功耗平衡 > 生态兼容性 > 模型精度上限

**对齐规格**：Echo v4.6 全量用户故事与验收标准规格书

## 1. 视觉编码模型 (Vision Encoder)

用于图片关键帧与视频截帧的语义向量化，是跨模态检索的视觉基石。v4.6 要求模型随 App 分发，无网络下载；支持低电量/过热降级切换。

| 选项                             | 优势                                                              | 劣势                                     | 适用场景                    | 决策状态     |
| -------------------------------- | ----------------------------------------------------------------- | ---------------------------------------- | --------------------------- | ------------ |
| **MobileCLIP-B LT**              | Apple 官方 Core ML；IN-1k 77.2%；iPhone 10.4ms；512d 嵌入；286MB | 精度低于 MobileCLIP2-S4 (81.9%)；512d 而非 768d | 唯一视觉模型（随 App 内置） | ✅ **当前**   |
| **MobileCLIP2-S4** 🔬             | IN-1k 81.9% 持平 SigLIP；445M params；768d                        | 无公共 Core ML 导出，待 ml-mobileclip 仓库更新 v2 架构 | Phase 2 优化目标        | 🔬 研究储备   |
| **SigLIP-SO400M (INT4)** ⛔       | （已弃用）                                                        | 被更优方案取代                       | 不适用                      | ❌ 已弃用     |
| **SigLIP 2 (SO400M)** ⛔          | （禁止）                                                          | 文本编码器膨胀至 708M 参数（token 嵌入表 393MB） | 不适合打包                  | ❌ 禁止       |

### 💡 决策依据 (v5.1b — 最终可用方案 — 2026-07-04)

- **MobileCLIP-B LT**（Apple 官方 `apple/coreml-mobileclip`）作为当前视觉模型。IN-1k 77.2%，512d 嵌入，iPhone 10.4ms 延迟，image 165MB + text 121MB = 286MB。**随 App 安装包分发**，使用 Core ML 加载。首次启动即可用，无 ODR 或额外下载流程。
- **为何不是 MobileCLIP2-S4**：MobileCLIP2-S4 是更优模型（IN-1k 81.9%, 768d），但 `apple/ml-mobileclip` 仓库尚未包含 v2 架构定义代码，无法完成 PyTorch → Core ML 转换。标记为 Phase 2 优化目标（等仓库更新）。
- **为何不是 SigLIP**：SigLIP-SO400M 无公共 Core ML 导出；SigLIP 2 文本编码器 708M 参数不适配端侧。均已弃用。
- **512d 维度影响**：当前嵌入维度为 512d（而非原计划的 768d），ProximaKit HNSW 索引在 Phase 1 创建时直接使用 512d。512d 对召回率影响轻微（HNSW 对小维度同样高效）。
- **模型加载失败处理**：若模型文件损坏或权限问题，显示“功能受限”提示，并提供“重试加载”按钮（仅重新加载本地文件，不发起网络请求）。无定时自动重试（符合 US-RES-004）。

## 2. 语音转写模型 (ASR)

用于语音备忘录离线转写。v4.6 要求转写仅本地完成，原始音频不持久化。

| 选项                              | 优势                                              | 劣势                         | 适用场景                    | 决策状态     |
| --------------------------------- | ------------------------------------------------- | ---------------------------- | --------------------------- | ------------ |
| **SenseVoice Small (q4_k GGUF)**  | 中文 CER 8.0%（Whisper base 31.3%）；129MB；多语言 50+；内置语言检测+情感 | 集成需适配 SenseVoice.cpp (ggml) | 主力转写引擎（随 App 内置） | ✅ **唯一**   |
| **Apple SFSpeechRecognizer**      | 系统级优化；零体积；实时流式                      | 中文离线依赖用户预下载系统词典；不可控 | 实时预览辅助                | 🔄 备选(实时预览) |
| **Whisper.cpp (base INT4)** ⛔     | （已弃用）                                        | 中文 CER 31.3%；被 SenseVoice 全面超越 | 不适用                      | ❌ 已弃用     |
| **Distil-Whisper** ⛔              | （禁止）                                          | 仅支持英文；无中文能力        | 不适用                      | ❌ 禁止       |

### 💡 决策依据 (v5.1 模型选型刷新 — 2026-07-04)

- **SenseVoice Small**（阿里巴巴 FunASR / Tongyi Lab）作为唯一 ASR 引擎。Q4_K GGUF 量化仅 **129MB**（比原 Whisper base 150MB 更小），中文 CER 从 31.3% 骤降至 **8.0%**（提升 3.9×）。英文 WER ~3.2%。非自回归 SAN-M + CTC 编码器：一次前向 → 全部 token，无自回归解码循环。
- **iOS 部署路径**：使用 `SenseVoice.cpp`（ggml + Metal 后端），与当前 whisper.cpp 集成模式完全一致。C++ 源代码可直接桥接至 Swift。Metal 加速后端在 Apple Silicon 上 ~20× 实时。
- **多语言内置**：原生支持 50+ 语言（zh/yue/en/ja/ko），语言检测、情感识别、音频事件检测均为内置能力，无需额外模型。
- **Whisper.cpp 弃用**：Whisper base 在中文上的 CER 高达 31.3%，实际不可用。Distil-Whisper 仅支持英文，不适用于中英双语场景。
- **Apple SpeechAnalyzer (iOS 26+) 排除**：虽然性能优异，但模型需首次使用时通过网络下载（`AssetInventory.downloadAndInstall()`），违反 Echo 红线 R-005。且仅支持 iOS 26+。
- **双引擎策略**：录音时使用 `SFSpeechRecognizer` 提供实时预览文字；保存后异步调用 SenseVoice 精转，融合结果作为最终记忆文本。原始音频不存储，仅保留转写文本（符合 US-ING-003）。
- **转写后处理**：自研标点恢复、数字规范化 Pipeline，提升检索友好度。
- **许可协议**：SenseVoice 使用 FunASR Model License（需在生产部署前确认与 Echo 许可兼容）。SenseVoice.cpp 运行时代码为 MIT。

## 3. 文本嵌入模型 (Text Embedding)

用于备忘录、转写文本、查询语句的语义向量化。v4.6 强调中英双语对齐，支持指令感知检索。

| 选项                                  | 优势                                                     | 劣势                                   | 适用场景                        | 决策状态     |
| ------------------------------------- | -------------------------------------------------------- | -------------------------------------- | ------------------------------- | ------------ |
| **multilingual-e5-small**             | 唯一公共 Core ML 嵌入模型；100+ 语言；224MB；社区验证     | 384d 而非 768d；精度低于 Qwen3          | 唯一文本嵌入模型（随 App 内置） | ✅ **当前**   |
| **Qwen3-Embedding-0.6B (INT4)** 🔬    | 继承 GTE-Qwen2；CMTEB-R 71.02；Matryoshka 1024→768d    | 无公共 Core ML 导出；需 PyTorch 转换    | Phase 2 优化目标                | 🔬 研究储备   |
| **EmbeddingGemma-300M**              | 极小型 (<200MB)；768d 原生；MTEB 69.67                  | 2K 上下文过短；无 Core ML 导出          | 备选方案                        | 🔄 备选       |
| **bge-m3-zh** ⛔                      | （禁止）                                                 | 无法与视觉模型对齐；破坏架构一致性      | 不适用                          | ❌ 不适用     |

### 💡 决策依据 (v5.1b — 最终可用方案 — 2026-07-04)

- **multilingual-e5-small**（Microsoft, `tamikisg/multilingual-e5-small-coreml` 社区 Core ML 导出）作为当前文本嵌入模型。224MB，384d 输出，支持 100+ 语言（zh/en/ja/ko 等）。**唯一公共可用的 Core ML 文本嵌入模型**。随 App 内置，无网络下载。
- **384d 维度**：当前嵌入维度为 384d（而非原计划的 768d）。384d 与 MobileCLIP-B LT 的 512d 视觉向量不在同一维度——文本检索和视觉检索使用**分离索引**（或通过零填充对齐）。对纯文本检索无影响；跨模态检索需额外对齐层。
- **为何不是 Qwen3-Embedding-0.6B**：Qwen3 是更优模型（CMTEB-R 71.02, 768d），但无公共 Core ML 导出（`tooktang` 仓库实际为 ExecuTorch/CoreAI 格式，仅兼容 iOS 27+）。需 PyTorch → Core ML 转换，标记为 Phase 2 优化目标。
- **为何不是 BGE/其他**：BGE 系列仅有 ONNX 导出（无 Core ML）；coremltools 9.0 已移除 ONNX 转换支持，ONNX→Core ML 路径不可用。multilingual-e5-small 是唯一可直接加载的选项。
- **降级处理**：模型加载失败时，仅提供 FTS5 关键词检索（符合 US-RES-004）。

## 4. 端侧向量数据库 (Vector Store)

存储与检索多模态向量。v4.6 要求支持增量更新、加密、断点续传进度存储（SQLite）。

| 选项                       | 优势                                                                            | 劣势                                                                 | 适用场景   | 决策状态         |
| -------------------------- | ------------------------------------------------------------------------------- | -------------------------------------------------------------------- | ---------- | ---------------- |
| **ProximaKit 1.7.0**       | 纯 Swift HNSW 图索引；余弦距离等 9 种度量；Actor 原生并发；WAL 日志持久化（.pxkt 二进制格式）；SPM 单行依赖；400+ 测试覆盖 | HNSW 增量更新需重建子图（append 模式追加新向量不重建）              | 主向量存储 | ✅ **首选**       |
| **LanceDB**                | 列式压缩；增量无锁；多语言 SDK（Python/Node.js/Java/Rust）                      | 无 Swift SDK；社区封装需 Rust 工具链 + XCFrameworks；破坏 NSFileProtection | 不适用     | ❌ 无 Swift SDK   |
| **SQLite + sqlite-vss**    | 事务安全                                                                        | 扩展维护停滞；不支持增量                                              | 风险高     | ❌ 不推荐         |
| **Faiss Mobile**           | 检索速度极致                                                                    | 无持久化/加密；不支持增量                                             | 不适用     | ❌ 不推荐         |

### 💡 决策依据（2026-07-04 更新，替代 v4.6 LanceDB 选型）

- **ProximaKit 1.7.0** 作为唯一向量引擎。纯 Swift 实现，零外部依赖，通过 SPM 单行引入。二进制持久化格式 `.pxkt`，随 App 沙盒创建，符合隐私要求。由 `VectorStoreActor`（Core/Actors/VectorStoreActor.swift）统一封装，对外暴露 Actor 隔离接口。
- **为什么放弃 LanceDB**：经 librarian Agent 调研确认（2026-07-04），LanceDB 官方仅提供 Python / Node.js / Java / Rust SDK，**无 Swift SDK**。C API（lancedb-c）无 iOS 支持。社区封装（LanceDbSwiftKit）要求引入 Rust 工具链和 XCFrameworks，且破坏 `NSFileProtectionComplete` 磁盘加密要求（不符合 Echo 红线 R-005）。基于上述不可逾越的工程障碍，LanceDB 被明确排除。
- **ProximaKit 选型理由**：HNSW 近似最近邻图索引，支持余弦距离、欧氏距离等 9 种度量；原生 Actor 隔离并发模型（符合 AGENTS.md §4.2 Actor 契约）；WAL 日志持久化保证写入安全；400+ 单元测试覆盖；二进制格式支持增量追加（append mode）。
- **断点续传辅助**：长任务（如全量索引构建）的进度使用独立 **SQLite 表 `TaskProgress`** 存储，而非向量存储引擎。进度记录在任务完成后自动删除，符合 US-SYS-001。

## 5. 推理执行框架 (Inference Runtime)

统一调度模型加载、量化、缓存与硬件加速。v4.6 明确移除 ODR，所有模型随 App 分发。

| 选项                       | 优势                                 | 劣势                           | 适用场景                        | 决策状态           |
| -------------------------- | ------------------------------------ | ------------------------------ | ------------------------------- | ------------------ |
| **Core ML**                | Apple 原生优化；ANE/GPU/CPU 自动调度 | 转换工具链偶发 bug             | 所有生产模型部署（视觉/嵌入/ASR CoreML） | ✅ **主力运行时**   |
| **MLX**                    | Apple 开源；Unified Memory 利用率高  | 与 Core ML 共存时内存管理复杂  | 未来统一推理层（评估中）        | 🔄 准生产备选       |
| **SenseVoice.cpp / ggml**  | SenseVoice ASR 专精优化；Metal 加速   | 仅适用 ASR 模型                | ASR 专用                        | ✅ **ASR 专用**     |
| **Apple Intelligence SDK** | 系统级集成                           | 黑盒不可审计；不可用于认知管线 | 仅限 Writing Tools 等非敏感场景 | ⚠️ **受限集成**     |

### 💡 决策依据 (v4.6 更新)

- **所有模型（MobileCLIP-B LT、multilingual-e5-small、SenseVoice Small）均随 App 安装包分发**，存放于 `Bundle.main`。App 内不发起任何网络下载请求，彻底移除 ODR（符合 US-RES-004）。
- **模型加载失败**：不提供自动重试，仅在 UI 上显示“重试加载”按钮，重新尝试加载本地文件。用户也可跳转系统设置修复 App（符合 US-RES-004）。
- **MLX 评估**：若 iOS 19 上 MLX 稳定性进一步提升且内存管理优于 Core ML，可考虑 V5.0 迁移。

## 6. 应用架构与状态管理 (App Architecture)

v4.6 延续 `@Observable + Actor` 模式，增强隐私校验、并发安全与统一错误处理。

| 选项                                 | 优势                                                | 劣势                            | 适用场景         | 决策状态   |
| ------------------------------------ | --------------------------------------------------- | ------------------------------- | ---------------- | ---------- |
| **@Observable + Actor 隔离**         | 原生高性能；精确刷新；与 Swift Concurrency 无缝集成 | 需自建副作用审计                | 所有业务管线     | ✅ **首选** |
| **TCA**                              | 单向数据流；Effect 可测试                           | 样板代码多；与 @Observable 重叠 | 不推荐用于新代码 | ❌ 过渡     |
| **SwiftUI + @Observable (无 Actor)** | 最简写法                                            | 并发不安全；副作用不可审计      | 纯展示组件       | ⚠️ 受限     |
| **Combine + MVVM**                   | 旧教程多                                            | 测试困难；内存泄漏              | 不用于新开发     | ❌ 已淘汰   |

### 💡 决策依据 (v4.6 更新)

- **统一错误响应矩阵**：工程中实现 `ErrorHandler` 协议，所有异步操作按 L1~L4 等级分类处理。L2 错误写入 `PendingOperations` 表，仅支持用户手动重试（无自动重放）。L1 重试 3 次后升级为 L2。
- **隐私校验 `PrivacyCheckpoint`**：每个 Pipeline 方法（如 `search`, `ingest`）必须调用 `PrivacyCheckpoint.validate()`，CI 强制覆盖率 100%。
- **断点续传**：使用 SQLite `TaskProgress` 表存储进度；任务完成后自动删除记录。取消任务时保存断点，下次启动时询问是否继续（符合 US-SYS-001）。
- **导航**：`NavigationStack` + `NavigationPath`，支持状态恢复。

## 7. 国际化与动态内容本地化 (i18n & Dynamic Localization)

v4.6 强调仅支持简体中文和英文，AI 输出语言与 UI 统一。

| 层级            | 技术方案                            | 适用范围             | 决策状态   |
| --------------- | ----------------------------------- | -------------------- | ---------- |
| **静态 UI**     | Xcode String Catalogs (.xcstrings)  | 按钮、标题、提示     | ✅ 标准     |
| **AI 动态内容** | Prompt 约束 + 结构化输出 + 语种校验 | 搜索结果、卡片、摘要 | ✅ 核心     |
| **数据存储**    | multilingual-e5-small 384d 嵌入 + 源语言元数据   | 跨语言检索           | ✅ 架构内建 |
| **运行时翻译**  | 禁用任何第三方/端侧翻译服务         | 无                   | ❌ 明确排除 |

### 💡 决策依据 (v4.6 更新)

- `preferredLanguage` 仅允许 `zh-Hans` 或 `en-US`。系统语言为繁体中文或其他方言时，默认 `zh-Hans`，首次启动提示一次。
- **AI 输出三重保障**：Prompt 注入语言参数 → 结构化 JSON 携带 `responseLanguage` → 后处理使用 `NaturalLanguage` 语种识别，不匹配则重试一次或返回模板回复。
- **跨语言检索**：依赖 multilingual-e5-small 的 100+ 语言对齐能力，无需翻译层。

## 8. 本地反馈学习机制 (Feedback Learning)

v4.6 新增纯本地反馈学习，支持点赞/点踩、时间衰减、权重截断。

| 组件          | 技术选型                                                     | 说明                  |
| ------------- | ------------------------------------------------------------ | --------------------- |
| **反馈存储**  | SQLite (FeedbackStore)                                       | 纯本地，永不上传      |
| **重排公式**  | `finalScore = cosineSim + clamp(Σ(👍*decay) - Σ(👎*decay), -0.5, 0.5)` | 阈值 ≥0.80 才应用反馈 |
| **时间衰减**  | 年龄 >90天 ×0.5；>180天归档                                  | 每条反馈独立计算      |
| **重置/撤销** | 清除表或删除单条记录                                         | 即时生效              |

### 💡 决策依据

- 完全符合 US-FBK-001/002/003，所有反馈数据仅存本地 SQLite，不设计任何上传逻辑。
- 余弦相似度阈值 0.80 及权重上限 ±0.5 在 `Retriever` 中实现，确保反馈学习稳定。

## 9. 后台任务与断点续传 (Background Tasks)

v4.6 明确要求后台任务面板、串行队列、SQLite 进度存储。

| 需求             | 技术方案                                                  |
| ---------------- | --------------------------------------------------------- |
| **后台任务注册** | `BGAppRefreshTask`, `BGProcessingTask`                    |
| **任务串行队列** | 自定义 `AsyncStream` + `Actor` 确保索引构建与数据同步互斥 |
| **进度存储**     | SQLite 表 `TaskProgress`（独立于向量库）                  |
| **断点续传**     | 取消时保存 `lastProcessedIndex`；重新开始询问用户         |
| **清理策略**     | 任务完成后自动删除进度记录                                |

### 💡 决策依据

- 符合 US-SYS-001。暂停/取消操作通过 `Task` 取消句柄实现。
- 进度展示使用 `Progress` 类型，绑定到 UI 状态。

## 10. 地理围栏与情境唤醒 (Geofencing)

v4.6 简化围栏重置规则：仅基于系统 `didExit` 后 `didEnter` 重置，永久停留不再重复推送。

| 组件         | 技术方案                                                     |
| ------------ | ------------------------------------------------------------ |
| **围栏监控** | `CLCircularRegion` + `CLLocationManager`                     |
| **重置逻辑** | 记录上次推送时间；收到 `didExit` 清除标记；`didEnter` 且无最近推送时触发 |
| **防打扰**   | 同一围栏 24h 内不重复（若未离开）                            |
| **权限关闭** | 静默禁用                                                     |

### 💡 决策依据

- 符合 US-AWK-001。不需要 30 秒持续离开判断，依赖 iOS 系统区域事件防抖。
- 推送内容匹配度 ≥0.7 由检索引擎计算。

## 11. 音乐推荐 (Music Suggestion)

v4.6 采用内置离线热门歌曲库，不依赖网络。

| 选项                | 优势                      | 劣势                      | 决策状态               |
| ------------------- | ------------------------- | ------------------------- | ---------------------- |
| **Apple Music API** | 个性化推荐质量高          | 需用户授权+订阅；API 限流 | 可选（若授权）         |
| **内置离线歌单**    | 零网络；稳定；随 App 更新 | 内容固化，无实时性        | ✅ **备选方案（主力）** |

### 💡 决策依据

- 若用户授权 Apple Music，优先使用 API 推荐，API 限流时静默降级至离线库。
