## 1. 视觉编码模型 (Vision Encoder)

用于图片关键帧与视频截帧的语义向量化，是跨模态检索的视觉基石。v4.6 要求模型随 App 分发，无网络下载；支持低电量/过热降级切换。

| 选项                             | 优势                                                              | 劣势                                     | 适用场景                    | 决策状态     |
| -------------------------------- | ----------------------------------------------------------------- | ---------------------------------------- | --------------------------- | ------------ |
| **SigLIP2-B/32** 🔬               | Apache-2.0 许可工件（R-5.1 已批准为商业候选）；SigLIP2 架构；多语言；`google/siglip2-base-patch32-256` | 约 1.5GB；Core ML 自转换进行中；无 iPhone 实机证据 | 视觉候选（转换中，需四类门禁） | 🔬 **转换中** |
| **MobileCLIP-B LT** ⛔            | Apple 官方 Core ML；IN-1k 77.2%；512d                            | **公共权重禁止商业使用**                  | 不适用                      | ❌ **淘汰（许可阻断）** |
| **MobileCLIP2-S4** ⛔             | IN-1k 81.9%；768d                                                | 同类公共权重限制；无公共 Core ML 导出     | 不适用                      | ❌ 淘汰       |
| **Apple Vision OCR** ✅           | 系统框架；零新增模型包；accurate 模式；zh-Hans/zh-Hant/en-US       | 仅文本识别（非语义向量）                  | OCR 文本通道（R-3.5）       | ✅ **采用**   |

### 💡 决策依据 (v6.0 — 模型路线重组 — 2026-08-01)

- **MobileCLIP-B LT 淘汰**：调研报告决策 4 确认 MobileCLIP 公共权重条款禁止商业产品使用，Echo 的 MIT 许可证不覆盖模型权重，仓库与公开来源中无 Echo 的单独书面授权。**不用于商业发布**。
- **SigLIP2-B/32 转换中**（R-5.1 决策 2026-08-01）：`google/siglip2-base-patch32-256` 精确工件 Apache-2.0 **已批准为商业发布候选**，Core ML 自转换进行中。需通过四类门禁：法律（完整 LICENSE/NOTICE/哈希登记）、转换一致性（PyTorch → Core ML，参考向量余弦相似度 > 0.995）、Echo 数据集实机评测、实体设备资源门禁。通过前不标记为生产就绪。
- **Apple Vision OCR 采用**：系统 Vision 框架 `VNRecognizeTextRequest`（accurate 模式），零新增模型包，作为 OCR 文本通道。识别文本经 E5 嵌入后写入独立 `ocr_text` generation。
- **模型加载失败处理**：若模型文件损坏或权限问题，显示"功能受限"提示，并提供"重试加载"按钮（仅重新加载本地文件，不发起网络请求）。无定时自动重试（符合 US-RES-004）。

## 2. 语音转写模型 (ASR)

用于语音备忘录离线转写。v4.6 要求转写仅本地完成，原始音频不持久化。

| 选项                              | 优势                                              | 劣势                         | 适用场景                    | 决策状态     |
| --------------------------------- | ------------------------------------------------- | ---------------------------- | --------------------------- | ------------ |
| **Whisper tiny (GGUF, bundled 衍生)** 🔬 | 官方 Whisper 衍生；whisper.cpp runtime；tiny ~39MB（R-5.4 已批准） | 中文 CER 高于 SenseVoice；SBOM 审查中 | ASR 路线（R-3.3，tiny） | 🔬 **tiny 批准** |
| **SenseVoice Small (q4_k GGUF)** ⛔ | 中文 CER 8.0%；129MB；多语言 50+                  | **FunASR 自定义条款 + 转换来源风险** | 不适用                      | ❌ **保守短名单排除** |
| **Apple SFSpeechRecognizer**      | 系统级优化；零体积；实时流式                      | 中文离线依赖用户预下载系统词典；iOS 26+ 资产需网络下载（违反 R-005） | 研究比较器（不进生产路由）  | 🔄 研究比较器 |
| **Distil-Whisper** ⛔              | （禁止）                                          | 仅支持英文；无中文能力        | 不适用                      | ❌ 禁止       |

### 💡 决策依据 (v6.0 — 模型路线重组 — 2026-08-01)

- **SenseVoice 保守短名单排除**：调研报告决策 4 确认 SenseVoice 使用 FunASR 自定义模型条款，转换来源风险高。**保守短名单排除**，不作为生产 ASR。
- **Whisper tiny 批准**（R-5.4 决策 2026-08-01）：bundled 官方 Whisper 衍生路线族，**tiny 变体（~39MB GGUF）已批准**（包体与风险平衡点；small 在法律审查通过后作为挑战者晋级）。R-3.3 实现时**必须生成完整 SBOM**（每个工件的来源 URL、固定 revision、SHA256、原始许可、NOTICE、转换脚本——延续 R-4 的 SHA256 校验框架）。**法律状态**：格式转换不授予新权利，源权重、runtime、转换器、量化和最终工件均需分别审查。
- **Apple SpeechAnalyzer (iOS 26+) 研究比较器**：模型需首次使用时通过网络下载（`AssetInventory.downloadAndInstall()`），违反 Echo 红线 R-005。仅作研究比较器，不进入生产路由。
- **iOS 部署路径**：whisper.cpp（ggml + Metal 后端）C interop 桥接至 Swift。音频预处理：AVAssetReader → PCM 16kHz mono → VAD。
- **转写后处理**：自研标点恢复、数字规范化 Pipeline，提升检索友好度。

用于备忘录、转写文本、查询语句的语义向量化。v4.6 强调中英双语对齐，支持指令感知检索。

| 选项                                  | 优势                                                     | 劣势                                   | 适用场景                        | 决策状态     |
| ------------------------------------- | -------------------------------------------------------- | -------------------------------------- | ------------------------------- | ------------ |
| **multilingual-e5-small**             | 公共 Core ML 嵌入模型；100+ 语言；224MB；384d 原生       | MS MARCO 训练来源下游含义待法律审查     | 文本嵌入（工程暂定）            | 🔶 **工程暂定（法律待审）** |
| **Qwen3-Embedding-0.6B (INT4)** 🔬    | 继承 GTE-Qwen2；CMTEB-R 71.02；Matryoshka 1024→768d    | 无公共 Core ML 导出；需 PyTorch 转换    | 挑战者（R-3.9）                | 🔬 挑战者     |
| **EmbeddingGemma-300M** 🔬            | 极小型 (<200MB)；768d 原生；MTEB 69.67                  | gated terms 下游接受义务待审；无 Core ML 导出 | 挑战者（R-3.9）            | 🔬 挑战者     |
| **bge-m3-zh** ⛔                      | （禁止）                                                 | 无法与视觉模型对齐；破坏架构一致性      | 不适用                          | ❌ 不适用     |

### 💡 决策依据 (v6.0 — 模型路线重组 — 2026-08-01)

- **multilingual-e5-small 工程暂定**：作为当前文本嵌入模型（384d 原生输出，不补零）。**法律状态**：MS MARCO 训练来源的下游含义交专业法律审查，不预设侵权结论。审查通过前标记为工程暂定。
- **384d 原生索引**：v6.0 采用独立 `text_dense/e5-v1` generation（384d HNSW），**不再补零至 512d**（调研报告判定补零为伪跨模态假设）。视觉检索使用独立 `vision_dense` generation。
  > 📌 **实现状态**：已接入（3F.3，2026-08-06）。`E5Embedder` 真实 384d 推理（Unigram tokenizer + CoreMLInferenceAdapter），**embedder 级原生 384d 输出（不补零）**；管道级 384→512 零填充待 `text_dense/e5-v1` generation 接线（3F.4/3F.6）后移除。参考向量 `e5-reference-vectors.json` 已提供（US-SRC-011）。DEF-34-003 loader 状态回报已关闭。
- **query/passage 前缀**：查询侧注入 `"query: "` 前缀，摄入侧注入 `"passage: "` 前缀（E5 指令感知检索）。
- **挑战者赛道**：Qwen3-Embedding-0.6B 与 EmbeddingGemma 进入挑战者赛道（R-3.9），需通过法律 + 质量 + 设备 + 迁移四类门禁。
- **离线生成运行时（Phase 3F / ADR-009，2026-08-04）**：grounded creation（US-SYN 批准子集）采用**不可变捆绑 LLM 运行时/工件 + 许可证 + 校验和**，并实现 `LanguageAligner`（语言对齐重试 ≤1，R-004）。模型随 App 分发、运行时零网络（R-005）；工件全部登记 `docs/05-planning/model-provenance-register.md`。
- **降级处理**：模型加载失败时，仅提供 FTS5 关键词检索（符合 US-RES-004）。
  > 📌 **实现状态**：计划态。FTS5 关键词降级由 R-3.6 词法通道（JiebaFTS5）提供；当前 `SearchPipeline` 在嵌入失败时抛出 `SearchError.embeddingFailed`，FTS5 降级路径待词法通道接入后实现。

## 3.5 词法通道与多通道融合 (v6.0 新增)

### 中文词法通道 (JiebaFTS5 + n-gram)

- **JiebaFTS5**：jieba 分词 + SQLite FTS5 自定义 tokenizer（C 扩展），中文精确分词。
- **字符 n-gram fallback**：bigram + trigram，覆盖 jieba 词典未登录词。
- **独立词法通道**：词法分数（BM25）不直接加到余弦分，走 RRF 融合。

### 加权 RRF 多通道融合

- **公式**：`score(d) = Σ w_i / (k_rrf + rank_i(d))`，`k_rrf = 60`（标准 RRF 常数）。
- **通道权重**（初始值，基于离线评测调整）：text_dense=1.0、vision_dense=0.8、ocr_text=0.6、lexical=0.5。
- **超时降级**：单通道超时（1.5s）被跳过，不影响其他通道结果。
- **每通道独立 rank**：不把原始余弦/BM25/规则分直接相加。
  > 📌 **实现状态**：部分实现。`SearchPipeline.rrfFuse` 融合算法已实现并测试；`text_dense` 通道由 3F.3 E5 真实推理驱动；`vision_dense` 通道待 SigLIP2 Core ML 转换完成（model-provenance-register §3），`ocr_text`/`lexical` 待 R-3.5/R-3.6 接入。

## 4. 端侧向量数据库 (Vector Store)

存储与检索多模态向量。v4.6 要求支持增量更新、加密、断点续传进度存储（SQLite）。

| 选项                       | 优势                                                                            | 劣势                                                                 | 适用场景   | 决策状态         |
| -------------------------- | ------------------------------------------------------------------------------- | -------------------------------------------------------------------- | ---------- | ---------------- |
| **ProximaKit 1.7.0**       | 纯 Swift HNSW 图索引；余弦距离等 9 种度量；Actor 原生并发；WAL 日志持久化（.pxkt 二进制格式）；SPM 单行依赖；400+ 测试覆盖 | HNSW 增量更新需重建子图（append 模式追加新向量不重建）              | 主向量存储 | ✅ **首选**       |
| **LanceDB**                | 列式压缩；增量无锁；多语言 SDK（Python/Node.js/Java/Rust）                      | 无 Swift SDK；社区封装需 Rust 工具链 + XCFrameworks；破坏 NSFileProtection | 不适用     | ❌ 无 Swift SDK   |
| **SQLite + sqlite-vss**    | 事务安全                                                                        | 扩展维护停滞；不支持增量                                              | 风险高     | ❌ 不推荐         |
| **Faiss Mobile**           | 检索速度极致                                                                    | 无持久化/加密；不支持增量                                             | 不适用     | ❌ 不推荐         |

### 💡 决策依据（2026-07-04 更新，替代 v4.6 LanceDB 选型）

- **ProximaKit 1.7.0** 作为唯一向量引擎。纯 Swift 实现，零外部依赖，通过 SPM 单行引入。二进制持久化格式 `.pxkt`，随 App 沙盒创建，符合隐私要求。由 `VectorStoreActor`（Core/Actors/VectorStoreActor.swift）统一封装，对外暴露 Actor 隔离接口。
- **分代索引（Phase R-A，2026-07-31）**：依据调研报告决策 1，`VectorStoreActor` 升级为**每代一个实例**的多实例架构，由 `GenerationRegistryActor` 持有 `[generationId: VectorStoreActor]` 字典。每个 `IndexGeneration` 对应独立 HNSW 文件（独立维度、独立模型空间），模型升级走新 generation，不覆盖当前索引。服务路由通过 `ActiveRouteSet` 原子切换，禁止混代服务。现有单一索引迁移为 `legacy-512-v1` generation。
- **为什么放弃 LanceDB**：经 librarian Agent 调研确认（2026-07-04），LanceDB 官方仅提供 Python / Node.js / Java / Rust SDK，**无 Swift SDK**。C API（lancedb-c）无 iOS 支持。社区封装（LanceDbSwiftKit）要求引入 Rust 工具链和 XCFrameworks，且破坏 `NSFileProtectionComplete` 磁盘加密要求（不符合 Echo 红线 R-005）。基于上述不可逾越的工程障碍，LanceDB 被明确排除。
- **ProximaKit 选型理由**：HNSW 近似最近邻图索引，支持余弦距离、欧氏距离等 9 种度量；原生 Actor 隔离并发模型（符合 AGENTS.md §4.2 Actor 契约）；WAL 日志持久化保证写入安全；400+ 单元测试覆盖；二进制格式支持增量追加（append mode）。
- **断点续传辅助**：长任务（如全量索引构建）的进度使用独立 **SQLite 表 `TaskProgress`** 存储，而非向量存储引擎。进度记录在任务完成后自动删除，符合 US-SYS-001。

## 5. 推理执行框架 (Inference Runtime)

统一调度模型加载、量化、缓存与硬件加速。v4.6 明确移除 ODR，所有模型随 App 分发。

| 选项                       | 优势                                 | 劣势                           | 适用场景                        | 决策状态           |
| -------------------------- | ------------------------------------ | ------------------------------ | ------------------------------- | ------------------ |
| **Core ML**                | Apple 原生优化；ANE/GPU/CPU 自动调度 | 转换工具链偶发 bug             | 生产模型部署（视觉/嵌入 CoreML） | ✅ **主力运行时**   |
| **whisper.cpp / ggml**     | Whisper ASR；Metal 加速；GGUF 量化   | 仅适用 ASR 模型                | ASR 专用（R-3.3 路线族）        | ✅ **ASR 专用**     |
| **MLX**                    | Apple 开源；Unified Memory 利用率高  | 与 Core ML 共存时内存管理复杂  | 未来统一推理层（评估中）        | 🔄 准生产备选       |
| **Apple Intelligence SDK** | 系统级集成                           | 黑盒不可审计；不可用于认知管线 | 仅限 Writing Tools 等非敏感场景 | ⚠️ **受限集成**     |

### 💡 决策依据 (v6.0 更新)

- **所有模型（multilingual-e5-small、Whisper GGUF、SigLIP2 checkpoint）均随 App 安装包分发**，存放于 `Bundle.main`。App 内不发起任何网络下载请求，彻底移除 ODR（符合 US-RES-004）。
- **ASR 运行时**：whisper.cpp / ggml（Metal 加速），替代原 SenseVoice.cpp（v6.0 路线重组，SenseVoice 保守短名单排除）。
- **模型加载失败**：不提供自动重试，仅在 UI 上显示"重试加载"按钮，重新尝试加载本地文件。用户也可跳转系统设置修复 App（符合 US-RES-004）。
- **MLX 评估**：若 iOS 19 上 MLX 稳定性进一步提升且内存管理优于 Core ML，可考虑 V5.0 迁移。

## 6. 应用架构与状态管理 (App Architecture)

v4.6 延续 `@Observable + Actor` 模式，增强隐私校验、并发安全与统一错误处理。

| 选项                                 | 优势                                                | 劣势                            | 适用场景         | 决策状态   |
| ------------------------------------ | --------------------------------------------------- | ------------------------------- | ---------------- | ---------- |
| **@Observable + Actor 隔离**         | 原生高性能；精确刷新；与 Swift Concurrency 无缝集成 | 需自建副作用审计                | 所有业务管线     | ✅ **首选** |
| **TCA**                              | 单向数据流；Effect 可测试                           | 样板代码多；与 @Observable 重叠 | 不推荐用于新代码 | ❌ 过渡     |
| **SwiftUI + @Observable (无 Actor)** | 最简写法                                            | 并发不安全；副作用不可审计      | 纯展示组件       | ⚠️ 受限     |
| **Combine + MVVM**                   | 旧教程多                                            | 测试困难；内存泄漏              | 不用于新开发     | ❌ 已淘汰   |

### 💡 决策依据 (v4.6 更新)

- **统一错误响应矩阵**：工程中实现 `ErrorHandler` 协议，所有异步操作按 L1~L4 等级分类处理。L2 错误写入 `PendingOperations` 表，仅支持用户手动重试（无自动重放）。L1 重试 3 次后升级为 L2。
- **隐私校验 `PrivacyCheckpoint`**：每个 Pipeline 方法（如 `search`, `ingest`）必须调用 `PrivacyCheckpoint.validate()`，CI 强制覆盖率 100%。
- **断点续传**：使用 SQLite `TaskProgress` 表存储进度；任务完成后自动删除记录。取消任务时保存断点，下次启动时询问是否继续（符合 US-SYS-001）。
- **导航**：`NavigationStack` + `NavigationPath`，支持状态恢复。

## 7. 国际化与动态内容本地化 (i18n & Dynamic Localization)

v4.6 强调仅支持简体中文和英文，AI 输出语言与 UI 统一。

| 层级            | 技术方案                            | 适用范围             | 决策状态   |
| --------------- | ----------------------------------- | -------------------- | ---------- |
| **静态 UI**     | Xcode String Catalogs (.xcstrings)  | 按钮、标题、提示     | ✅ 标准     |
| **AI 动态内容** | Prompt 约束 + 结构化输出 + 语种校验 | 搜索结果、卡片、摘要 | ✅ 核心     |
| **数据存储**    | multilingual-e5-small 384d 嵌入 + 源语言元数据   | 跨语言检索           | ✅ 架构内建 |
| **运行时翻译**  | 禁用任何第三方/端侧翻译服务         | 无                   | ❌ 明确排除 |

### 💡 决策依据 (v4.6 更新)

- `preferredLanguage` 仅允许 `zh-Hans` 或 `en-US`。系统语言为繁体中文或其他方言时，默认 `zh-Hans`，首次启动提示一次。
- **AI 输出三重保障**：Prompt 注入语言参数 → 结构化 JSON 携带 `responseLanguage` → 后处理使用 `NaturalLanguage` 语种识别，不匹配则重试一次或返回模板回复。
- **跨语言检索**：依赖 multilingual-e5-small 的 100+ 语言对齐能力，无需翻译层。

## 8. 本地反馈学习机制 (Feedback Learning)

v4.6 新增纯本地反馈学习，支持点赞/点踩、时间衰减、权重截断。

| 组件          | 技术选型                                                     | 说明                  |
| ------------- | ------------------------------------------------------------ | --------------------- |
| **反馈存储**  | SQLite (FeedbackStore)                                       | 纯本地，永不上传      |
| **重排公式**  | `finalScore = cosineSim + clamp(Σ(👍*decay) - Σ(👎*decay), -0.5, 0.5)` | 阈值 ≥0.80 才应用反馈 |
| **时间衰减**  | 年龄 >90天 ×0.5；>180天归档                                  | 每条反馈独立计算      |
| **重置/撤销** | 清除表或删除单条记录                                         | 即时生效              |

### 💡 决策依据

- 完全符合 US-FBK-001/002/003，所有反馈数据仅存本地 SQLite，不设计任何上传逻辑。
- 余弦相似度阈值 0.80 及权重上限 ±0.5 在 `Retriever` 中实现，确保反馈学习稳定。

## 9. 后台任务与断点续传 (Background Tasks)

v4.6 明确要求后台任务面板、串行队列、SQLite 进度存储。

| 需求             | 技术方案                                                  |
| ---------------- | --------------------------------------------------------- |
| **后台任务注册** | `BGAppRefreshTask`, `BGProcessingTask`                    |
| **任务串行队列** | 自定义 `AsyncStream` + `Actor` 确保索引构建与数据同步互斥 |
| **进度存储**     | SQLite 表 `TaskProgress`（独立于向量库）                  |
| **断点续传**     | 取消时保存 `lastProcessedIndex`；重新开始询问用户         |
| **清理策略**     | 任务完成后自动删除进度记录                                |

### 💡 决策依据

- 符合 US-SYS-001。暂停/取消操作通过 `Task` 取消句柄实现。
- 进度展示使用 `Progress` 类型，绑定到 UI 状态。

## 10. 地理围栏与情境唤醒 (Geofencing)

v4.6 简化围栏重置规则：仅基于系统 `didExit` 后 `didEnter` 重置，永久停留不再重复推送。

| 组件         | 技术方案                                                     |
| ------------ | ------------------------------------------------------------ |
| **围栏监控** | `CLCircularRegion` + `CLLocationManager`                     |
| **重置逻辑** | 记录上次推送时间；收到 `didExit` 清除标记；`didEnter` 且无最近推送时触发 |
| **防打扰**   | 同一围栏 24h 内不重复（若未离开）                            |
| **权限关闭** | 静默禁用                                                     |

### 💡 决策依据

- 符合 US-AWK-001。不需要 30 秒持续离开判断，依赖 iOS 系统区域事件防抖。
- 推送内容匹配度 ≥0.7 由检索引擎计算。

## 11. 音乐推荐 (Music Suggestion)

v4.6 采用内置离线热门歌曲库，不依赖网络。

| 选项                | 优势                      | 劣势                      | 决策状态               |
| ------------------- | ------------------------- | ------------------------- | ---------------------- |
| **Apple Music API** | 个性化推荐质量高          | 需用户授权+订阅；API 限流 | 可选（若授权）         |
| **内置离线歌单**    | 零网络；稳定；随 App 更新 | 内容固化，无实时性        | ✅ **备选方案（主力）** |

### 💡 决策依据

- 内置离线热门歌曲库：按年份分类，每年 20 首，随 App 版本更新（JSON 文件）。不依赖网络，符合本地优先原则。
- 若用户授权 Apple Music，优先使用 API 推荐，API 限流时静默降级至离线库。
